Feature Discovery

Inline Document Comments

Anchored discussions for long-form documents in Acme Docs.

Reviewers should be able to highlight any range of text and start a discussion thread that survives edits, mentions, and version history without overwhelming participants with notifications. The discovery is mid-cycle: anchoring behavior and mobile UX are the open structural questions; notifications, permissions, and mentions are converging.

ANC-01 When commented text is edited, do anchors migrate, orphan, or auto-resolve? Spec blocker

Three behaviors are technically feasible. Each has different UX implications: migration preserves intent but can drift; orphaning preserves intent literally but visually clutters; auto-resolve is clean but discards in-progress conversation. We need a default, and we need an opt-out.

ANC-03 Anchoring on fully-deleted text — orphan visibly, auto-archive, or refuse the delete?

Open question whether deleting commented text should be allowed at all without warning. Refusing the delete creates a footgun for restructure-heavy authors (Lina); allowing the delete silently risks data loss.

PERM-01 Should viewers be able to comment by default, or only commenters?

Acme Docs has three roles today: viewer, commenter, editor. The new feature blurs the viewer/commenter line — ad-hoc reviewers like Priya are usually given viewer access and asked to "leave a note." Either we promote viewer to comment-by-default, or we make commenter the more common share role.

MOB-01 Inline annotation gesture vs bottom sheet — which is the primary mobile UX?

Inline gesture (long-press to comment) is faster but real estate is brutal. Bottom sheet preserves doc visibility but adds a tap. Need user testing — currently no mobile prototype exists.

Decisions Ratified

3 ADRs
ADR-001 Ratified

Reuse MentionPicker component

Rationale

The existing MentionPicker in the sharing flow is well-tested and already supports the autocomplete patterns Acme Docs users expect. Building a parallel picker would create divergent UX and double the maintenance burden.

Resolves

MNT-01

Build a comment-specific picker (rejected — divergent UX, 2× maintenance)

ADR-002 Ratified

Email digest cadence — 2-hour rolling

Rationale

2-hour cadence balances Marcus's signal-to-noise need (he mutes per-comment notifications) with Lina's need for same-day awareness (a daily digest misses end-of-day reviews). Tested in Q1 cohort: opt-out rate 8% vs 31% for per-comment.

Resolves

NTF-03

Per-comment email (rejected — opt-out rate 31%); daily digest (rejected — misses same-day reviews)

ADR-003 Ratified

Anchoring algorithm — range-fingerprint

Rationale

Range-fingerprint stores a small content-derived signature alongside character offsets. Survives small edits within the anchor range and disambiguates when offsets drift. Implementation maps to the existing Diff service.

Resolves

Anchoring foundation (informs ANC-01, ANC-03)

Explicit character offsets (rejected — fragile under any edit); semantic anchors (rejected — over-engineered for v1)

4
Author edits text
Anchored range is touched. Decision pending: ANC-01 determines migrate vs orphan vs auto-resolve. ANC-02 may surface confirmation.
5
Resolve
Author or commenter resolves. Resolved threads are read-only and cannot be deleted (audit trail per PERM-02 leaning).

Risk Register

5 risks tracked
High

Comment orphaning on text edits — data-loss flavor

If anchoring fails on edit and threads silently disappear, users lose conversation history they expected to be durable. This is the failure mode that turns a productivity feature into a trust-eroding one.

Mitigation: ANC-01 must explicitly choose visible behavior (orphan with badge, not silent removal). Anchoring algorithm (ADR-003) chosen for edit-survival. Failure-mode test required in spec.

High

Notification fatigue across the participant pool

Comment threads naturally fan out. Without strict scope discipline, every doc participant gets pinged on every reply. Marcus already mutes channels for this reason; we'd push him to mute the product.

Mitigation: NTF-01 ratified mentioned-only push. ADR-002 caps email cadence at 2hr digest. NTF-02 still open — must land before launch.

Medium

Mobile UX regression in Acme Docs reading mode

Inline gesture (long-press) collides with the existing text-selection menu on iOS. Bottom sheet adds friction to reading-only sessions where 80% of comment-light viewers (Priya cohort) live.

Mitigation: MOB-01 requires user testing on both patterns before spec. Mobile WG to deliver prototype by end of week.

Medium

Performance at 1000+ comments per document

Long-running specs and contracts can accumulate hundreds of threads. Inline rendering, anchoring fingerprint computation, and notification fan-out all become expensive at scale.

Mitigation: Spec must include performance budget (p95 doc open < 600ms with 1000 comments). Render virtualization required. Notification fan-out batched server-side.

Medium

Privacy: notifying mentioned non-collaborators

Mentioning a user outside the doc's collaborator list could leak doc title or comment text in the notification preview. Worst case: confidential project names exposed via Slack/email previews.

Mitigation: MNT-02 open, blocking on Legal review. Default: notification omits doc title; recipient must request access to see context.
